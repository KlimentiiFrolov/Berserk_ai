# Схема документов и metadata (Sprint 1: rules + FAQ)

Версия схемы: 1. Источник правды в коде: `berserk_ingest/schema.py` (pydantic, `extra="forbid"`, валидаторы по типу источника).

## 1. Форматы источников

### Правила — `.docx`
- Файл: «Расширенные Правила ККИ "Берсерк"», версия **8.0-1 от 04.09.2026** (версия и дата читаются из заголовка документа).
- Структура: `Часть N` (Heading 1) → раздел `105. Базовые свойства.` (Heading 2) → вложенные пункты. В документе 108 разделов.
- **Номера пунктов (`105.2.3`) в тексте отсутствуют** — это автонумерация Word. Загрузчик берёт `(numId, ilvl)` каждого абзаца и шаблоны уровней из `numbering.xml`
  (например `105.%1.%2.`), `normalize/numbering.py` повторяет счётчики Word. Проверка корректности: 185 из 188 перекрёстных ссылок вида «пп. 105.4»
  из самого текста правил указывают на восстановленные пункты. Остальные три (`536.5.3.1` ×2, `517.3`) указывают на пункты, которых в документе нет; это похоже
  на устаревшие ссылки в самих правилах и вынесено в отчёт прогона (`refs_unresolved`).
- Маркированные абзацы и ненумерованные продолжения склеиваются с предыдущим пунктом. Исключение — Часть 7 (терминология): там каждый маркер верхнего уровня = термин.
- Две таблицы (таблица способностей, таблица ударов) сериализуются построчно («метка | колонка: значение; …») и становятся отдельными чанками.
- **Картинки-символы** (65 уникальных, 289 вставок) заменяются на `[символ]` / `[символ: имя]`. Имена берутся из `data/symbols.json` (`{"<хеш>": "кристалл"}`),
  шаблон и сами картинки выгружает `python -m berserk_ingest symbols`. Пока имён нет, все символы выглядят одинаково (`[символ]`) — это известное ограничение.

### FAQ — Google Sheets (одна вкладка = один выпуск карт)
- Колонки: `Номер | Название | Вопрос | Ответ | Ответ утвержден`. Колонки ищутся по названиям в строке заголовка (запасной вариант — позиции A–E).
- «Номер» и «Название» заполнены **только в первой строке блока карты**; остальные строки блока пустые в этих колонках — значения протягиваются вниз.
- «Вопрос» может быть пустым: запись — уточнение по карте (`faq_kind = ruling`), а не вопрос-ответ (`qna`).
- Строка-преамбула «Это FAQ по картам …» — не контент, пропускается. Вопрос без ответа пропускается и считается в отчёте (`unanswered`).
- «Ответ утвержден» — чекбокс (в CSV: `TRUE` / `FALSE` / пусто).
- В Sprint 1 заведена одна вкладка (`4. Ложные боги`, gid `522308198`). Остальные добавляются в `config.FAQ_SHEETS` или через `--gid/--set-name`.

## 2. Единица чанка

| Источник | Чанк | Размер |
|---|---|---|
| rules | один пункт / подпункт / термин / таблица. Длинные (> 1600 символов) режутся по абзацам и предложениям, суффикс `#N` | на реальных правилах: 1247 чанков, медиана 360, p95 1126, максимум 1612 символов |
| faq | одна запись: вопрос-ответ **или** уточнение по карте | короткие |

Текст чанка самодостаточен (эмбеддер не видит metadata):

```
# rules (подпункт)
Правила ККИ «Берсерк» 8.0-1 | Часть 1. Основные принципы игры “Берсерк”. Свойства и особенности
105. Базовые свойства
Родительский пункт 105.2: Элитность. Принадлежность карты к элитной (…) или к рядовой (…).
105.2.3. Если стоимость карты имеет переменную величину Х, то её владелец должен определить значение Х при наборе отряда. …

# faq
FAQ: Ложные боги
Карта: Стражник Тугарда
Вопрос: Могут ли два стоящих в строю … поменяться местами дважды …?
Ответ: Могут. Состоятся два последовательных обмена местами.
```

## 3. Поля `ChunkMetadata`

| Поле | Тип | rules | faq | Описание |
|---|---|---|---|---|
| `chunk_id` | str | ✔ | ✔ | стабильный ключ; из него строится id точки Qdrant (`uuid5`) |
| `doc_id` | str | ✔ | ✔ | `rules_8.0-1` / `faq_4`; по нему синхронизируется переиндексация |
| `source_type` | `rules` \| `faq` | ✔ | ✔ | |
| `priority` | `official` \| `community` | всегда `official` | из «Ответ утвержден» | фильтр/буст для пункта бэклога 5 |
| `source_version` | str | `8.0-1` | имя вкладки | |
| `snapshot_date` | YYYY-MM-DD | дата версии из заголовка docx | дата скачивания из `.meta.json` | **не время запуска** (иначе payload менялся бы при каждом прогоне) |

Payload точки в Qdrant = `metadata` (без пустых полей) + `text`. Payload-индексы (keyword): `source_type`, `priority`, `doc_id`, `approval_status`, `card_name`.

## 4. Правила вывода полей (нужно согласовать с Product Owner)

1. **`priority` для FAQ:** `approved` → `official`; `not_approved` и `unknown` → `community`.
   Старый код различал три уровня (100 / 85 / 75). Сейчас «не утверждено» и «неизвестно» слиты в `community`;
   `approval_status` сохраняется в payload, так что при необходимости retrieval может различать их без переиндексации.
2. **Правила** всегда `official`.
3. **Идентификаторы.** FAQ: `faq_<ключ>_<sha1[:12] от (вкладка, номер, карта, вопрос, ответ)>` — не зависит от номера строки, перестановка строк id не меняет,
   но правка текста ответа меняет id (поэтому режим синхронизации удаляет старые точки по `doc_id`). Rules: `rules_<версия>_<номер пункта>`.
4. **Сообщество (Telegram/VK)** в Sprint 1 не входит; для него зарезервирован `source_type = "community"` в следующей версии схемы.

## 5. Известные ограничения Sprint 1

- Имена символов не заполнены (65 картинок), поэтому «число над символом [символ]» пока неинформативно.
- Часть 7: два раздела без номера в заголовке («Символы.», «Комментарий к формулировкам текстов карт.») получают id из названия.
- Три неразрешённых перекрёстных ссылки в правилах (см. выше).
- Вкладки FAQ кроме «4. Ложные боги», «Чек-лист на игру», «Важные турнирные моменты» и база карт не загружаются.
- Колонка «Ответ утвержден» проверена на логике, но не на реальном CSV: на момент разработки таблица была доступна только как веб-страница, где чекбоксы не видны.
  Первым делом выполните `--refresh` и посмотрите строку `approved/not_approved/unknown` в выводе.
