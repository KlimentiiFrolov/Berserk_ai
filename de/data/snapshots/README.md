# Снапшоты входных данных

Здесь лежат зафиксированные входные данные, на которых строится воспроизводимый прогон.

| Файл | Что это | Как получить |
|---|---|---|
| `rules_<версия>.docx` | docx правил (ровно один файл `rules*.docx`) | положить вручную |
| `faq_<ключ>.csv` + `faq_<ключ>.meta.json` | CSV вкладки FAQ и дата/хеш скачивания | `python -m berserk_ingest chunks --source faq --refresh` |

Правила:
- Пайплайн читает снапшоты и **не ходит в Google Sheets**, пока нет `--refresh` (или самого файла).
- Обновили таблицу → `--refresh` → закоммитили новые `.csv` и `.meta.json` одним коммитом.
- `snapshot_date` в payload берётся из `.meta.json` (`fetched_at`), а не из времени запуска, поэтому
  одни и те же файлы всегда дают одинаковые чанки (проверяется `chunks_sha256` в `data/build/manifest.json`).
- Файл правил весит несколько МБ (картинки). Если репозиторий не должен его хранить, используйте Git LFS.
- Фикстура `tests/fixtures/faq_4_sample.csv` — это 28 строк для тестов, а не снапшот. В эту папку её не копировать.
