# Обработка ошибок

Необязательные настройки `.env` (значения по умолчанию):

```dotenv
BOT__REQUEST_TIMEOUT_S=120
BOT__TELEGRAM_TIMEOUT_S=15
BOT__TELEGRAM_RETRY_AFTER_S=5
```

`REQUEST_TIMEOUT_S` ограничивает один вызов `rag.answer()`: поиск, ожидание
очереди и генерацию. Таймаут LLM остаётся отдельной настройкой `LLM__TIMEOUT_S`.
При таймауте бот отменяет ожидание и сообщает пользователю о задержке.
Уже выполняющийся CPU-инференс в `asyncio.to_thread` или генерация на удалённом
сервере могут продолжиться: отмена Python-задачи не гарантирует их остановку.

Ошибка хотя бы одной запрошенной коллекции Qdrant сообщает о недоступности
поиска, а не об отсутствии информации. Пустой успешный поиск по-прежнему
означает отсутствие контекста; реранкер для пустого списка не запускается.

Запросы к Telegram имеют отдельный таймаут. Только при явном ответе 429
допускается один повтор после указанной Telegram задержки, если она не больше
`TELEGRAM_RETRY_AFTER_S`. Сетевые ошибки, 5xx, запрет доступа и некорректные
запросы логируются без повторной отправки. После сетевого сбоя неизвестно,
получил ли Telegram сообщение, поэтому повтор может создать дубликат.
О сбое доставки нельзя надёжно сообщить через тот же недоступный канал.

При ошибке отправки части длинного ответа следующие части не отправляются.
Уже записанный ответ остаётся в SQLite. Ошибка подтверждения callback не
отменяет сохранённую оценку и не запускает повторную запись.

Typing работает в отдельной задаче. Сбой typing не мешает выдаче ответа;
при завершении обработки или отмене запроса фоновая задача отменяется и ожидается.

Автотесты воспроизводят ошибки без обращения к реальным Telegram/Qdrant/LLM.
Ручную сквозную проверку нужно провести на подключённых сервисах.
